01

The Data Contract

Every trigger is normalized into one of these two event shapes before any logic runs. Built manually inside each platform's automation rules.

Freshdesk-Origin Event

event_typestring"ticket_created" or "ticket_updated"
source_systemstringalways "FRESHDESK"
freshdesk_ticket_idstringFreshdesk's own ticket ID
manageengine_ticket_idstr | nullnull until first linked
tagsarraychecked for "IT-Desk-Synced"
ticket_dataobjectsubject, desc, priority, status

ManageEngine-Origin Event

event_typestring"request_created" or "updated"
source_systemstringalways "MANAGEENGINE"
manageengine_ticket_idstringManageEngine's request ID
freshdesk_ticket_idstr | nullnull until first linked
request_dataobjectsubject, desc, priority, status

Example JSON Payload

{
  "event_type": "ticket_updated",
  "source_system": "FRESHDESK",
  "freshdesk_ticket_id": "FD-10294",
  "manageengine_ticket_id": "ME-88371",
  "tags": ["urgent", "IT-Desk-Synced"],
  "ticket_data": {
    "subject": "VPN connection drops every 10 minutes",
    "priority": "High"
  }
}
Note: Getting manageengine_ticket_id onto the Freshdesk side requires a new custom field.

ID Translation & Matching

Freshdesk to ManageEngine

SEARCH ManageEngine.Requests
WHERE freshdesk_ticket_id = incoming.freshdesk_ticket_id

ManageEngine to Freshdesk

SEARCH Freshdesk.Tickets
WHERE manageengine_ticket_id = incoming.manageengine_ticket_id

Change detection: live-vs-live, not a stored hash

meHash = zoho.encryption.sha256(subject + "|" + description + "|" + fdPriority.toString() + "|" + fdStatus.toString());
fdHash = zoho.encryption.sha256(fdSubject + "|" + fdDescription + "|" + fdCurrentPriority.toString() + "|" + fdCurrentStatus.toString());

if (fdHash == meHash)
{
    return {"status": "skipped", "reason": "no_change"};
}
Why not a stored hash: the design in Section 04 assumes a last_sync_hash custom field on both platforms. It doesn't actually exist on Freshservice — a PUT including it was rejected live with invalid_field. So instead of comparing against a remembered value, both sides are re-hashed fresh on every run and compared directly.
